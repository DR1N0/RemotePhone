# Go backend consolidation — roadmap

> **Project status: paused indefinitely (v0.0.1).** The roadmap is historical; no further phases are planned. See the [README](../../README.md) for the post-mortem.

Living index of remaining implementation phases. Update status in place as work proceeds; this is not a substitute for the per-phase plan files it links to.

| # | Phase | Status | Scope |
|---|---|---|---|
| 0 | Module skeleton | Done | Go module skeleton, migrations+sqlc pipeline, controller dispatch skeleton. |
| 0a | Auth | Done | Password hashing, bearer tokens, bootstrap secret, user/credential/registration-invite lifecycle, scope middleware, auth routes on both surfaces. |
| 1 | [Instance foundation](instance-foundation.md) | Done | `audit` + `placement` + `instance` CRUD/lifecycle against one configured worker (no spawning yet). Verified end-to-end against the real `remotephone-worker` binary (real Android Studio Emulator boot/stop), not just unit tests. |
| 2 | [Session & transport redesign](session-transport-redesign.md) | Done | `session` + `transport` packages, clientapi routes, main.go wiring. Includes the PIN-based invite redesign and the `TransitionAttachmentRole` promote/demote redesign. Verified end-to-end against the real `remotephone-worker` binary (real emulator boot, session create, PIN invite + guest redeem, promote/demote, signaling relay, disconnect + transport teardown, instance stop) — not just unit tests. |
| 3 | [Admin & reconciliation](admin-reconciliation.md) | Done | `admin` port, audit-log retrieval routes, owner-absence probe wired into the controller. Verified end-to-end against the real `remotephone-controlplane` binary (admin setup, user/credential management, cross-owner instance list, audit retrieval, owner-absence reconciler closing an expired session) — no `remotephone-worker` run required for this phase, unlike Phases 1/2. |
| 4 | [Worker lifecycle](worker-lifecycle.md) | Done | Real `exec.Command` spawning: one `remotephone-worker` process per running instance, health-checked and respawned on failure. No placement/affinity logic — 1:1 model, see `docs/architecture/decisions-log.md` (2026-10-14). Verified end-to-end against the real `remotephone-worker` binary and a real Android Studio Emulator — create/start/crash-respawn-adopt/stop, including confirming the emulator process survives a worker crash untouched. |
| 5 | [Pairing & TLS identity](tls-identity.md) | HTTPS done; PIN-pairing deferred | PIN-pairing trust bootstrap, HTTPS for the client surface. Scope split with the user: HTTPS + self-signed cert infra is done; PIN-pairing stays deferred until the protocol is concretely specified. The Android client exists now but currently accepts any certificate. |
| 6 | Base image & template model | Implemented and verified with a 38GB real-game base | `templates`/`base_images` tables, `image.Service` capture-candidate/promote routes, and worker-side QCOW2 layering: `CaptureBaseImage` flattens the full userdata chain plus the encryption-key overlay into a standalone base, and new instances get a thin `qemu-img` overlay and the base key instead of a full copy. Verified through the real control plane with a 64GB AVD and a 38GB Zenless Zone Zero base copied from a phone (capture → promote → clone boot → resources present, base hash unchanged). Remaining: per-instance base pinning/GC, async capture with progress, data-partition sizing UI, and Admin Images UI. See `docs/architecture/decisions-log.md` (2026-10-27). |
| 7 | Windows host + multi-instance per owner | Done | Native Windows build/test/serve, WHPX emulators, AMD `h264_amf` (probe now uses real capture dimensions), platform-specific process stop/liveness, adb-first graceful emulator shutdown, per-instance port allocation, template discovery + `GET /api/v1/templates`, and migration `0014` removing the one-instance-per-owner constraint. Verified end-to-end on Windows: two concurrent instances on distinct ports, both streaming 30fps H.264; the Flutter Android client lists both and streams one with touch input. Also fixed the multi-slice H.264 RTP grouping bug this surfaced. See `decisions-log.md` (2026-10-22). |
| 8 | Audio + multi-touch | Implemented; audio+touch+video verified on a real phone over LAN | Emulator `streamAudio` → 8 kHz mono PCMU WebRTC track; emulator `sendTouch` with pointer IDs replacing per-event adb input. Client adds an audio transceiver and plays it; `getevent` confirms two-slot multi-touch. Real phone streams ~30fps video and ~50 audio packets/s. Fixed a resampler panic, AMF's missing periodic IDRs, and ICE candidate selection (now advertises all routable IPv4; no Tailscale-specific config). **Quickboot caveat**: a stop/start can restore a wedged guest audio state (near-silent 136-byte `streamAudio` packets); a guest cold reboot fixes it, and instances should cold-boot or detect this. See `decisions-log.md` (2026-10-22 entries). |

Dependency order: 1 → 2 → 3 roughly follow the TS service dependency graph (audit is a leaf; instance needs audit; session needs instance; admin needs audit + the attachment-transport machinery session/transport build). 4 and 5 are independent of each other and of 2/3, but both assume 1. 6 depends on 1 and 4. 7 depends on 1–5 and is the current product baseline. 8 builds on 7's worker/transport path.
