# Go backend consolidation — roadmap

Living index of remaining implementation phases. Update status in place as work proceeds; this is not a substitute for the per-phase plan files it links to.

| # | Phase | Status | Scope |
|---|---|---|---|
| 0 | Module skeleton | Done | Go module skeleton, migrations+sqlc pipeline, controller dispatch skeleton. |
| 0a | Auth | Done | Password hashing, bearer tokens, bootstrap secret, user/credential/registration-invite lifecycle, scope middleware, auth routes on both surfaces. |
| 1 | [Instance foundation](instance-foundation.md) | Done | `audit` + `placement` + `instance` CRUD/lifecycle against one configured worker (no spawning yet). Verified end-to-end against the real `mako-worker` binary (real Android Studio Emulator boot/stop), not just unit tests. |
| 2 | [Session & transport redesign](session-transport-redesign.md) | Done | `session` + `transport` packages, clientapi routes, main.go wiring. Includes the PIN-based invite redesign and the `TransitionAttachmentRole` promote/demote redesign. Verified end-to-end against the real `mako-worker` binary (real emulator boot, session create, PIN invite + guest redeem, promote/demote, signaling relay, disconnect + transport teardown, instance stop) — not just unit tests. |
| 3 | [Admin & reconciliation](admin-reconciliation.md) | Done | `admin` port, audit-log retrieval routes, owner-absence probe wired into the controller. Verified end-to-end against the real `mako-controlplane` binary (admin setup, user/credential management, cross-owner instance list, audit retrieval, owner-absence reconciler closing an expired session) — no `mako-worker` run required for this phase, unlike Phases 1/2. |
| 4 | [Worker lifecycle](worker-lifecycle.md) | Done | Real `exec.Command` spawning: one `mako-worker` process per running instance, health-checked and respawned on failure. No placement/affinity logic — 1:1 model, see `docs/architecture/decisions-log.md` (2026-10-14). Verified end-to-end against the real `mako-worker` binary and a real Android Studio Emulator — create/start/crash-respawn-adopt/stop, including confirming the emulator process survives a worker crash untouched. |
| 5 | [Pairing & TLS identity](tls-identity.md) | HTTPS done; PIN-pairing deferred | PIN-pairing trust bootstrap, HTTPS for the client surface. Scope split with the user: HTTPS + self-signed cert infra is done; PIN-pairing stays deferred until a real native client exists to pair with and verify against. |
| 6 | Base image & template model | Implemented, unit-tested; live E2E verification inconclusive — **retest after a host restart before trusting either way** | `templates`/`base_images` tables, `image.Service` capture-candidate/promote routes, all backed by unit tests (including the qcow2-overlay-merge fix below). Live boot-from-promoted-image attempts hung 3/3 times — but a follow-up control test (a *plain* instance, no base image involved at all) also degraded badly (90+ seconds and climbing vs. an established ~35-second baseline from earlier the same session), pointing at host-level exhaustion from an extremely long dev session rather than a confirmed defect in the capture/merge code. See `docs/architecture/decisions-log.md`'s 2026-10-20 entries (two, same day) for the full investigation and bisection. Per-instance-AVD-cleanup-on-delete shipped as a prerequisite and *is* confirmed working live, repeatedly, throughout this investigation. |

Dependency order: 1 → 2 → 3 roughly follow the TS service dependency graph (audit is a leaf; instance needs audit; session needs instance; admin needs audit + the attachment-transport machinery session/transport build). 4 and 5 are independent of each other and of 2/3, but both assume 1. 6 depends on 1 and 4.
