# RemotePhone v0.0.1 — paused prototype

This is the first and final public snapshot of **RemotePhone**, a self-hosted
Android emulator streaming experiment.

It was built around one idea: run several Android emulator instances on your own
machine, stream each one to a phone with real touch input, and let a few people
each have their own "phone". The control plane, Flutter client, instance
lifecycle, QCOW2 base-image layering, WebRTC video/audio, touch input, and
orientation handling all work.

It was stopped because the games that motivated it — **Zenless Zone Zero**,
**Genshin Impact**, and other heavy miHoYo titles — do not survive the Android
x86_64 emulator's ARM translation layer. After login, the games load
`libtersafe2.so` (Tencent anti-cheat), and the process aborts in
`libndk_translation`:

```text
Fatal signal 6 (SIGABRT)
Abort message: 'Guest call didn't restore sp: expected ..., actual ... -0x10'
#04 libndk_translation.so (berberis::ExecuteGuestCall)
```

Clearing the Vulkan PSO cache only caused a ~261 MB re-download; it did not
change the crash. This is an anti-cheat/translation boundary, not a rendering
bug in RemotePhone. Bypassing it was not a responsible product direction.

The repository is published so the useful parts survive: the control plane,
access-code/certificate-pinning auth, QCOW2 base images, and the
WebRTC/touch/orientation pipeline. It can still run light, emulator-friendly
Android apps, but it is not a product and has no support.

## Release asset

`RemotePhone-v0.0.1.apk` is a Flutter **release-mode** build, but it is signed
with the local debug keystore (this project never had a production signing
setup). It is suitable for sideloading and inspection only. Package id:
`com.remotephone.client`.

Read the [full bilingual post-mortem](https://github.com/DR1N0/RemotePhone#readme).

## 中文

这是 **RemotePhone** 的唯一公开版本，也是一个已经暂停的实验项目。

它原本想做的是：在自己的电脑上开多台 Android 模拟器，把画面和原生触摸串到手机上，让几个人各有一台独立的“手机”。控制面、Flutter 客户端、实例生命周期、QCOW2 基础镜像分层、WebRTC 音视频、触摸和横竖屏处理都是能工作的。

放弃的原因是：绝区零、原神等米哈游游戏在 Android x86_64 模拟器的 ARM 翻译层里过不了反作弊。登录后加载 `libtersafe2.so`，进程在 `libndk_translation` 中 `SIGABRT`。清 shader cache 只会重新下载约 261MB，没有解决问题；这是反作弊和翻译层的边界，不是渲染 bug，也不适合靠绕过反作弊来做产品。

仓库保留下来，是为了让控制面、访问码/证书固定、QCOW2 基础镜像、WebRTC/触摸/方向处理这些部分还能被复用。它仍然可以跑轻量的、对模拟器友好的 Android 应用，但不是产品，也没有支持。
